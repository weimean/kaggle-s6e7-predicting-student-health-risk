# Portfolio Conversion — Design

**Date:** 2026-07-19
**Goal:** Convert this working competition repo into a public-facing portfolio piece for GitHub repo `kaggle-s6e7`.

## Framing

The headline is the workflow, validated by the result: *"I directed an AI pair through a full Kaggle competition using a hypothesis-driven workflow — and every point of the final score (public LB 0.95048, top 15.5% of 2192) is accounted for in a ledger."* Attribution is fully transparent: the AI pairing is the story, not a footnote.

Audience is layered: a recruiter gets the story from the README in 2–3 minutes (result, figures, pairing model); a technical reader descends through WORKFLOW.md → experiments.md → notebooks → src.

Voice rules: README and WORKFLOW.md are written in the user's first person ("I directed…", "we ran…" for the pair). Notebooks keep their original explain-as-we-build voice untouched — they are primary evidence of the process.

## Changes

### New files
- **README.md (rewritten):** hook + result; score-arc figure; "the pairing model" section stating honestly who did what (Claude wrote code/analysis and proposed hypotheses; the user set direction, questioned reasoning at checkpoints, and made every go/no-go call); story-in-7-notebooks table; the six transferable lessons; reproduce section; link to WORKFLOW.md and experiments.md.
- **WORKFLOW.md:** the operating system of the collaboration — brainstorm → spec → plan → milestone execution with checkpoints; the experiment-ledger contract (hypothesis → single change → same folds/seed → keep only if ΔCV ≥ +0.0005); artifact caching / checkpoint pattern for long notebooks; the Python-3.12 torch side-venv workaround; parallel background training jobs; the competitor-scouting agent; what transfers to real ML work.

  1. Score arc 0.333 → 0.9505 with annotated levers (log-style step chart)
  2. CV vs public LB calibration scatter across all 7 submissions (the ±0.001 agreement)
  3. Error-correlation heatmap of the final blend members with their greedy weights

## Publishing

- Create public GitHub repo `kaggle-s6e7` via `gh`; push existing history as-is (milestone commits are process evidence). If `gh` is not authenticated, hand the user the commands instead.

## Quality gates

- Figures produced by committed script, not pasted images.
- All README/WORKFLOW relative links verified against the final tree.
- Notebooks spot-checked to render on GitHub (outputs already embedded).
- Final sweep for private scratch references (absolute local paths, background task IDs) in the two new docs — notebooks' `../data/` relative paths are fine.
- No competition data files committed (already gitignored); confirm before push.

## Out of scope

- Re-voicing or re-executing notebooks; GitHub Pages/HTML rendering; Kaggle-side publication; any further modeling.
