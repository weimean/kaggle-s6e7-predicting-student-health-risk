# Portfolio Conversion — Design

**Date:** 2026-07-19
**Goal:** Convert this working competition repo into a public-facing portfolio piece for GitHub repo `kaggle-s6e7`.

## Framing

**The project is the headline; the pairing is transparent context.** The README leads with the ML work itself: *"A hypothesis-driven run at Kaggle Playground S6E7 — public LB 0.95048, top 15.5% of 2192, with every point of the score accounted for in an experiment ledger."* The metric detective story, the falsified hypotheses, the CV discipline, and the ensemble reasoning are the substance. The AI collaboration is disclosed plainly — a "How this was built" section in the README plus WORKFLOW.md for the full protocol — but it frames *how* the work was done, not *what* the piece is about.

Audience is layered: a recruiter gets the project from the README in 2–3 minutes (result, figures, method); a technical reader descends through experiments.md → notebooks → WORKFLOW.md → src.

Voice rules: README and WORKFLOW.md are written in the user's first person ("I directed…", "we ran…" for the pair). Notebooks keep their original explain-as-we-build voice untouched — they are primary evidence of the process.

## Changes

## Publishing

- Create public GitHub repo `kaggle-s6e7` via `gh`; push existing history as-is (milestone commits are process evidence). If `gh` is not authenticated, hand the user the commands instead.

## Quality gates

- Figures produced by committed script, not pasted images.
- All README/WORKFLOW relative links verified against the final tree.
- Notebooks spot-checked to render on GitHub (outputs already embedded).
- Final sweep for private scratch references (absolute local paths, background task IDs) in the two new docs — notebooks' `../data/` relative paths are fine.
- No competition data files committed (already gitignored); confirm before push.

## Out of scope

- Re-voicing or re-executing notebooks; GitHub Pages/HTML rendering; Kaggle-side publication; any further modeling.
